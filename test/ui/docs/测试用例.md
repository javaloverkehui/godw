# GoDW 控制台 · UI 测试用例（交互 + 数据预期）

> 写在前面的两句话
>
> 1. 每个用例都有一个人：他为什么来这一页、想做成什么、失败了会怎样。
>    没有人物动机的用例，最后都会退化成「点一遍不报错」。
> 2. 每条写操作都配一条数据库预期。页面说成功只是「前端认为成功」，
>    库里对得上才是「这件事真的发生了」。

执行方式见 `../README.md`。文中用例编号与 spec 里的 `test('TC-xxx')` 一一对应，
用 `npx playwright test -g "TC-DS-03"` 可以单独跑。

## 1. 认证与会话

人物：刚拿到账号的运营。他关心三件事：坏令牌会不会白屏、密码错了有没有提示、刷新要不要重登。

环境说明：dev 后端允许匿名并视为 admin，所以「未登录」用「本地放一个坏令牌 → `/me` 401」构造——
这正是令牌过期时用户的真实遭遇。

| 编号 | 场景 | 交互预期 | 数据库预期 |
| --- | --- | --- | --- |
| TC-AUTH-01 | 令牌过期后打开控制台 | 骨架照常渲染；右上角「角色」变成「登录」；点开弹窗字段正确；Esc 关闭且遮罩不残留 | 前端清掉坏令牌（`localStorage` 里不再有 `godw.token`） |
| TC-AUTH-02 | 密码输错 | 提示「邮箱或密码错误」这类可读文案（**不是**「登录已过期」）；弹窗不关闭，能重试 | 不写令牌；`app_user.password_hash` 与登录前完全一致 |
| TC-AUTH-03 | 密码正确 | 提示「已登录」；弹窗关闭；徽标显示 `role: admin` | 令牌落地；用该令牌请求 `/me` 返回 200，且 `userId` 能在 `app_user` 里对上同一账号 |
| TC-AUTH-04 | 刷新页面 | 仍是登录态；工作区徽标仍在 | 徽标上的工作区名 = `workspace` 里当前用户所属的那一行 |

> 这条用例在第一次运行时抓到一个真 bug：登录接口返回 401 时，
> 前端不问青红皂白提示「登录已过期，请重新登录」。已修复为「只有带令牌被拒才算过期」。

## 2. 工作台

人物：每天上班先看这一屏的负责人。他不点二级页，只靠四个数字和一条链路判断「昨天怎么样」。

| 编号 | 场景 | 交互预期 | 数据库预期 |
| --- | --- | --- | --- |
| TC-OVW-01 | 打开工作台 | 四张卡：数据源 / 模型 / 管道 / 近期成功率；数据源卡片小字给出已采集表数 | 三个计数分别等于 `datasource` / `model` / `pipeline` 的本工作区行数；表数等于 `dataset` 行数 |
| TC-OVW-02 | 看「最近运行」 | 最多 12 行，按时间倒序；每行显示实例号后 8 位、管道名、业务日期、状态 | 与 `instance` 最近 12 行逐行一致（实例号、管道、日期、状态映射） |
| TC-OVW-03 | 看「近期成功率」 | 百分比 + 「最近 N 次运行」 | = 最近 12 条实例里 success 占比四舍五入 |
| TC-OVW-04 | 看「链路健康」 | 每条管道一行，显示调度、节点 pill、最近状态 | 行数 = `pipeline` 行数；每行状态 = 该管道 `instance` 最新一条，无记录则「未运行」 |
| TC-OVW-05 | 点一行运行记录 | 抽屉打开，标题是管道名 + 业务日期 + 实例 ID；节点统计卡等于节点数；关闭后不残留 | 节点数 = `task_instance` 行数；每个 `node_id` 都出现在节点表里 |

## 3. 数据源接入

人物：新来的数据工程同学，接入公司第一个 PostgreSQL。他手会抖：忘填名字、端口写成 1、密码打错。

核心诉求：**失败时不许留半条脏记录**。

| 编号 | 场景 | 交互预期 | 数据库预期 |
| --- | --- | --- | --- |
| TC-DS-01 | 正常接入 | 提示「数据源已接入」；列表出现该行，地址与「正常」状态可见 | `datasource` 落库：type=postgres、status=ok、config 四项正确、`secret_enc` 非空、`checked_at` 非空；接口响应不含 `secret`/`password` 字段 |
| TC-DS-02 | 名称留空点保存 | 提示「请填写名称」；弹窗不关；其他字段不被清空 | 一个创建请求都不发；`datasource` 无对应行 |
| TC-DS-03 | 端口填 1（必然连不上） | 错误提示含「连接/拒绝/失败」线索；弹窗保留以便就地改 | 不落库（「连不上不入库」是承诺，不是文案） |
| TC-DS-04 | 对已接入数据源点「测试」 | 提示「连接正常」 | `status=ok` 且 `checked_at` 比之前更晚（时间戳前移） |
| TC-DS-05 | 点「采集」 | 提示「已采集 N 张表」 | `dataset` 中该数据源的行数 = N；不存在「零字段」的空壳表快照 |
| TC-DS-06 | 删除数据源 | 二次确认；提示「已删除」；行消失 | `datasource` 行消失，且该数据源的 `dataset` 被级联清空（不留孤儿） |

## 4. 模型定义与发布

人物：负责 DWD 层的数据开发。他怕两件事：YAML 写错没人拦；「发布成功」但库里没有版本，下次重跑拿到新定义。

每个用例用自己的模型名，互不影响。

| 编号 | 场景 | 交互预期 | 数据库预期 |
| --- | --- | --- | --- |
| TC-MODEL-01 | 预览 DDL | 弹出/展开 DDL，含 `CREATE TABLE`、列定义、主键 | `model` 无新行（预览只是编译，不落库） |
| TC-MODEL-02 | 模型名不符合分层前缀（`bad_xxx`） | 提示「建模规范校验未通过」并说明应匹配 `dwd_`；弹窗保留可改 | `model`、`model_version` 都无新行 |
| TC-MODEL-03 | 首次发布 | 提示「模型 X 已发布 v1」；左侧树出现该模型并标 v1 | `model.active_version=1`；最新 `model_version`：version=1、status=published、DDL 含表名与主键、列数=2 |
| TC-MODEL-04 | 加一列再发一次 | 提示「已发布 v2」 | `active_version=2`；版本表两行（v1/v2）；**v1 的 description 仍是「第一版」**（历史快照不被覆盖） |
| TC-MODEL-05 | 删除模型 | 确认按钮在输入完整模型名之前保持禁用；输错一个字也不放行；删完提示并移出树 | `model` 行消失；该模型全部 `model_version` 级联删除 |

## 5. 管道编排与实例运行

人物：值班运维。动作都是「出事了才做」：停管道、手动补一次、批量重跑、翻某次运行卡在哪个节点。

| 编号 | 场景 | 交互预期 | 数据库预期 |
| --- | --- | --- | --- |
| TC-PIPE-01 | 新建管道向导 | 没勾模型点下一步 → 「至少选一个要产出的模型」；发布后进入结果页「X 已发布 v1」 | `pipeline`：active_version=1、enabled=true、schedule 为空（选「手动」）；`pipeline_version`：published、1 个节点、节点 model=dwd_order |
| TC-PIPE-02 | 停用 / 启用 | 按钮文案在「停用/启用」之间切换；提示「已停用」「已启用」 | `pipeline.enabled` 依次变 false / true |
| TC-PIPE-03 | 立即运行（连点两次） | 每次提示「已创建实例 XXXXXXXX」；自动跳到运行实例页并加载 | 每次都是**新实例**（手动触发是「再跑一次」，不覆盖历史）；trigger_type=manual；每个实例各有 1 条 `task_instance` |
| TC-PIPE-04 | 实例筛选与分页 | 先按管道筛到自己的 2 条；再按状态筛，条数与库一致，行状态不混入别的状态；空结果给「没有符合条件的实例」；每页 10 条时不超过 10 行 | 各筛选条件下条数 = `instance` 对应 where 计数；两条实例都已进入终态 |
| TC-PIPE-05 | 批量重跑 | 勾选后出现「已选 1 条」；重跑提示「重跑完成：成功 1」；勾选区清空 | 新增一条 `trigger_type=retry` 的实例，指向同一管道 |
| TC-PIPE-06 | 打开实例详情 | 抽屉显示管道/业务日期/实例 ID；节点表行数 = 节点数；渲染 SQL 有内容（不是一直「加载中」） | 节点表与 `task_instance` 一一对应；SQL 来自该次运行的版本快照 |
| TC-PIPE-07 | 编辑描述并发布 | 提示「已发布 X v2」 | `active_version=2`、`description` 更新；版本表 v1/v2 都在；**历史运行条数不变**（只改描述不该丢历史） |

## 6. 自助查询（只读 SQL）

人物：临时想核对一个数的分析师。他只会敲 SQL，不会写代码。

这个页面的价值有两条：数要真查出来；写操作必须被挡住——一个「只读」入口如果能删库，比没有更危险。

| 编号 | 场景 | 交互预期 | 数据库预期 |
| --- | --- | --- | --- |
| TC-SQL-01 | `select id,name from workspace` | 表头 id/name，行数正确 | 与直连查询结果**逐行一致**（ID、名称、顺序） |
| TC-SQL-02 | 尝试 `update workspace set name='hacked'` | 错误块含「只允许 SELECT」和「当前是 UPDATE」 | 目标行的 `name` 一字未改 |
| TC-SQL-03 | 一次提交两条语句 | 错误块含「单条语句」 | — |
| TC-SQL-04 | `generate_series(1,500)`，上限 100 | 提示「100 行 · 已截断到 100 行」；表格正好 100 行 | — |
| TC-SQL-05 | 查询命中 0 行 | 显示「查询成功，没有返回行」，不渲染空表格 | — |
| TC-SQL-06 | 光标在编辑器里按 Ctrl+Enter | 不发请求到别处，直接出结果 1 行，值 = 7 | — |

人物：数据安全负责人 + 业务方。负责人要确认策略真存下来了、分享页真的没有内部导航、每步写操作查得到人；
业务方只关心「点开链接就能看，不用登录」。

| 编号 | 场景 | 交互预期 | 数据库预期 |
| --- | --- | --- | --- |
| TC-GOV-01 | 新增列级脱敏 | 提示「列策略已保存」；列表出现该表/列/分级 | `column_policy` 落库：classification=secret、mask_type=phone |
| TC-GOV-02 | 新增行级策略再删除 | 保存提示后行出现；删除有二次确认；提示「已删除」后行消失 | `row_policy` 落库（role=viewer、filter 原文一致、说明一致）；删除后按 id 查为 0 |
| TC-GOV-03 | 创建分享链接 | 提示「链接已复制/已创建」；列表出现令牌 | `share_link`：kind=metric、target=gmv、有效期 6–7 天；**匿名**打开 `#/share/<token>` 能看到标题、面包屑「分享视图」、侧栏隐藏、执行/主题按钮隐藏、刷新可用；删除后令牌行消失且公开页提示「分享链接不存在或已过期」 |
| TC-GOV-04 | 删除一条行级策略 | 审计页首行出现该动作 | `audit_log` 最新一行：action=`policy.row.delete`、resource=策略 id、actor 非空 |

## 10. 数据文档与 BI 图表

人物：接手一张陌生表的分析师，和被要求「把图表嵌进周报」的运营。
这两页最容易退化成「长得像文档的静态页」，所以断言都落在「与元数据一致」。

| 编号 | 场景 | 交互预期 | 数据库预期 |
| --- | --- | --- | --- |
| TC-CAT-01 | 数据文档里选一张已发布模型 | 中栏列出字段表；「物理表」显示定义里的表名 | 字段行数与名称集合 = 该模型 `model_version.spec.columns`（当前生效版本）；物理表名 = spec.table 或模型名 |
| TC-CAT-02 | 在文档搜索框输入一个字段名 | 左侧能定位到持有该字段的模型 | 该字段确实属于这条模型的当前版本 spec |
| TC-BI-01 | 打开 BI 图表页并选一张图 | 列表条数正确；预览显示「N 个数据点」；点「查看 SQL」在页内展开 SQL | 图表条数 = `public.chart` 本工作区行数；展开的 SQL 指向该图表的 dataset |

## 覆盖边界（没测什么，为什么）

- **画布拖拽、图表 hover**：依赖像素坐标，回归价值低于维护成本；由人工走查覆盖。
- **真实引擎建表（applyDDL）**：会在用户数据源里建物理表，测试不做，交由 `test/integration` 用一次性库验证。
- **多租户隔离的写入**：切换工作区会改令牌与全局视图，串行用例里做容易污染；当前只验证了工作区徽标与归属。
- **`audit_log` 清理**：审计是追加型数据，测试动作留痕但不删除——清审计比留痕更糟。
