E01 工程基座（8 人日）

T0101 · 仓库骨架与依赖边界 P0 1d

目标：建立能长期演进、AI 不会写乱的目录结构。 要点 - 严格按 docs/03 第 1 节创建 cmd/internal/pkg 三层；internal 内按领域分包，禁止建 utils 大杂烩。 - 只允许单向依赖：api → service → repo/domain，executor → connector。 - 引入 depguard 规则写入 .golangci.yml，违规即 CI 失败。 - go.mod 声明 module github.com/<org>/godw，Go 版本 1.22。 产出：目录树、go.mod、.golangci.yml、根 README.md。 验收：go build ./...、go vet ./...、golangci-lint run 全部通过；空包都有 doc.go 说明职责。

T0102 · 配置系统 P0 1d

目标：一份配置跑多环境，敏感信息不落盘。 要点 - config.yaml + 环境变量覆盖，前缀 GODW_，层级用 _ 连接（GODW_DB_HOST）。 - 结构体用 validator 标签做必填/范围校验，启动失败要打印具体字段名和来源。 - 支持 config.dev.yaml / config.prod.yaml 叠加；--config 指定路径。 - 敏感项只允许从环境变量或 secret 文件读，禁止写默认值。 产出：internal/config/config.go、loader.go、config.example.yaml。 验收：三条优先级（默认 < 文件 < 环境变量）单测通过；缺 db.host 时启动报 config: db.host is required (source: default)。

T0103 · 日志、错误码与链路 ID P0 1d

目标：出问题能凭一个 ID 定位全链路。 要点 - zap JSON 输出，固定字段 ts/level/msg/request_id/trace_id/workspace_id/instance_id。 - pkg/errs 定义 AppError{Code int, Msg string, Cause error, Meta map[string]any}，实现 Unwrap()；提供 Wrap/Is/As。 - 错误码常量集中在 pkg/errs/codes.go，分段与 API 文档一致（10xxx/20xxx/30xxx/40xxx/50xxx）。 - HTTP 中间件生成 request_id（ULID），注入 ctx 与响应头 X-Request-Id；panic 恢复为 500 并记录堆栈。 产出：pkg/errs/*、internal/obs/log/*、中间件。 验收：构造 3 层包装错误，errors.Is 能命中底层；panic 请求返回统一 JSON 且日志含 stack。

T0104 · 迁移与 sqlc 接入 P0 1.5d

目标：schema 变更可追溯、可回滚，查询类型安全。 要点 - goose 迁移放 migrations/，命名 0001_init.sql；每个迁移必须写 -- +goose Down。 - sqlc.yaml 按领域分 package（meta、scheduler、bi），emit_pointers_for_null_types: true。 - 连接池 pgx/v5，参数：max_conns=20、min_conns=2、max_conn_lifetime=30m。 - 迁移作为独立命令执行（godw migrate up），server 启动只校验版本，不自动迁移。 产出：迁移脚本、sqlc.yaml、internal/meta/repo/db.go。 验收：空库执行 make migrate 成功；sqlc generate 后 git diff --exit-code 无变更；重复迁移幂等。

T0105 · HTTP 基础层 P0 1.5d

目标：所有接口共享一致的入参校验、响应与错误处理。 要点 - 中间件顺序：recover → requestID → accessLog → auth → rbac → audit → rateLimit。 - 统一响应封装 {code,message,data,requestId}；分页解析 page/pageSize/sort，pageSize 上限 200。 - 入参用 DTO + binding 标签，错误转成 20xxx 并返回字段级信息。 - CORS、gzip、健康检查 /healthz、就绪 /readyz（检查 DB 与迁移版本）。 产出：internal/api/http/router.go、middleware/*、response/*。 验收：非法 body 返回 400 + 字段名；/readyz 在 DB 断开时返回 503；中间件顺序有单测。

T0106 · OpenAPI 契约 P0 1d

目标：前后端并行开发，接口变更可审查。 要点 - 手写 api/openapi.yaml（3.1），用 oapi-codegen 生成 server 接口与 TS 类型。 - CI 用 oasdiff 检查 breaking change，破坏性变更需 PR 标签 api-breaking。 - 生成物提交入库，禁止运行期反射生成文档。 产出：api/openapi.yaml、api/gen/*、web/src/api/types.ts。 验收：make api-gen 无 diff；oasdiff 在删除字段时报错。

T0107 · 本地开发环境 P0 1d

目标：新人一条命令起全套依赖。 要点 - deploy/docker-compose.dev.yaml：postgres:16、redis:7、mysql:8、clickhouse:24、minio。 - 初始化脚本建库 godw、建只读账号、创建 CH 测试库 dw。 - make up / down / reset / seed；seed 灌入样例业务表（订单 10 万行）。 产出：compose 文件、deploy/init/*.sql、Makefile。 验收：make reset && make migrate && make seed && make smoke 全绿；冷启动 ≤ 90s。

T0108 · CI 流水线 P0 1d

目标：质量门禁自动化。 要点 - 任务：lint（golangci-lint）、test（-race -coverprofile）、build（多架构）、docker image、web lint+build。 - 缓存 Go module 与 pnpm store；PR 必跑，main 分支额外跑 integration。 - 覆盖率低于阈值（70%）直接失败。 产出：.github/workflows/ci.yaml、.golangci.yml。 验收：故意提交 lint 错误与失败测试，CI 均能拦住。

T0109 · 集成测试框架 P0 1d

目标：连接器与 SQL 逻辑必须跑真库。 要点 - testcontainers-go 启 PG/MySQL/CH；DuckDB 用内存模式。 - 提供 testkit.NewPG(t) 返回已迁移 + 已 seed 的实例，测试结束自动清理。 - 集成测试加 //go:build integration，make test-integration 单独跑。 产出：test/testkit/*、示例测试 3 个。 验收：make test-integration 5 分钟内完成；并行测试互不干扰（随机 schema 名）。

T0110 · CLI 骨架 P0 1d

目标：所有能力都能脚本化。 要点 - cobra 子命令：serve/worker/migrate/version/doctor/config/apply/plan/export/run/backfill。 - 全局 --config、--workspace、--env、--output json|table。 - doctor 检查：DB 连通、迁移版本、Redis、对象存储、引擎连通性。 产出：cmd/godw-cli/*、internal/cli/*。 验收：godw doctor 在依赖缺失时逐项输出 FAIL 与修复建议；--output json 可被 jq 解析。

E02 元数据与数据源（14 人日）

T0201 · 元数据 DDL 与 ER P0 2d

目标：把 docs/02 的设计落成可执行迁移。 要点 - 实现第 2.1–2.7 节全部表、索引、约束、分区；分区表先建 3 个月分区。 - 所有表带 created_at/updated_at，写操作靠触发器或应用层统一填充（二选一，全库一致）。 - 唯一约束必须覆盖业务幂等键，禁止只靠应用层判重。 产出：migrations/0002_meta.sql 等、docs/er.png（可用 mermaid 替代）。 验收：重复插入 (pipeline_id,node_key,biz_date) 报唯一冲突；\d+ task_instance 可见分区与索引。

T0202 · Repository 层 P0 2d

目标：数据访问集中、可控、可测。 要点 - 每个聚合一个 repo（ModelRepo/PipelineRepo/InstanceRepo/...），方法首参 ctx。 - 提供 WithTx(ctx, fn)，事务内复用同一 Queries；禁止在 repo 里开 goroutine。 - 更新带乐观锁：WHERE id=$1 AND version=$2，影响行数 0 → errs.ErrConflict（HTTP 409）。 - 查询方法必须支持分页与过滤，禁止 SELECT * 无 limit 暴露给 API。 产出：internal/meta/repo/*.go、tx.go。 验收：并发更新同一模型，一个成功一个 409；repo 测试跑真 PG 且覆盖软删除过滤。

T0203 · 工作空间与环境 P0 1d

目标：多项目、多环境隔离的最小闭环。 要点 - workspace 创建时自动建 dev/prod 两个 env 与 default 资源组。 - env.bindings 维护「逻辑别名 → datasource_id」，提供解析函数 ResolveDatasource(alias, env)。 - 删除 workspace 用软删除 + 级联校验（有运行中实例时拒绝）。 产出：service/handler/DTO、解析函数与单测。 验收：同一模型在 dev/prod 解析出不同数据源；有运行实例时删除返回 409。

T0204 · 数据源管理 P0 2d

目标：安全地存连接信息并验证可用性。 要点 - 密码走 secret 表：AES-256-GCM，密钥来自环境变量 GODW_SECRET_KEY（32 字节），支持 key_version 轮换。 - 连接串按类型拼装，参数集中在 connector/dsn.go，禁止字符串拼接 SQL。 - 测试连接超时 5s，返回耗时与版本号；失败区分「网络不可达 / 认证失败 / 库不存在」。 - 列表接口不回传密码，只回 hasPassword: true。 产出：internal/meta/service/datasource.go、internal/connector/dsn.go、加密工具。 验收：DB 中 secret 表无明文；错误密码返回 50002 auth failed；测试接口 5s 内必返回。

T0205 · 连接器接口与注册表 P0 2d

目标：新增数据源不改核心代码。 要点 - 实现 docs/03 第 2 节 Connector 接口与 Register/Open；工厂签名 func(ctx, Config) (Connector, error)。 - 连接池按 datasource_id 缓存，sync.Map + 引用计数，空闲 10 分钟回收。 - 所有方法必须响应 ctx 取消；Query 返回的 Rows 必须可 Close 且幂等。 - 提供 connectortest 套件：一套接口测试跑遍所有实现。 产出：types.go、registry.go、pool.go、connectortest/suite.go。 验收：注册表并发注册/获取无 race（-race 通过）；ctx 取消后 Query 1s 内返回。

T0206 · 四个首期连接器 P0 4d

目标：覆盖 80% 使用场景。 要点 - PostgreSQL（pgx）、MySQL（go-sql-driver）、ClickHouse（clickhouse-go v2）、DuckDB（嵌入式）。 - 每个实现 Capabilities()：PG/MySQL MergeUpsert=true；Doris InsertOverwrite=true；ClickHouse InsertOverwrite=false, ReplacePartition=true（CH 无 INSERT OVERWRITE，只有 REPLACE PARTITION）；DuckDB 单机全支持。能力声明错一个，写入策略就会生成跑不通的 SQL，必须有集成测试兜底。 - 类型映射表落在 dialect/<engine>/types.go，覆盖 string/int/float/decimal/date/timestamp/bool/json/array。 - 大结果集用 Stream，CH 必须用 native 协议而非 HTTP。 产出：connector/{postgres,mysql,clickhouse,duckdb}/*。 验收：connectortest 全通过；10 万行导出内存增长 < 100MB；Cancel 后服务端查询确实终止（查 pg_stat_activity / system.processes）。

T0207 · 元数据采集 P0 2d

目标：不连库也能看到表结构。 要点 - 统一 Collector 接口：Collect(ctx, schema) ([]TableMeta, error)，各引擎用 information_schema / system.tables / DESCRIBE。 - 计算结构指纹 fingerprint = sha256(sorted(column name+type+nullable))，与库中比对判断是否变化。 - 大表行数用估算（pg_class.reltuples、system.parts），不做 COUNT(*)。 - 采集结果写 meta_table，保留上次指纹用于变更对比。 产出：connector/*/collect.go、internal/meta/service/collect.go。 验收：1000 张表采集 ≤ 30s；新增一列后再次采集能识别 add_column。

T0208 · 采集调度与变更告警 P1 1.5d

目标：表结构漂移能被发现。 要点 - 支持手动刷新与定时刷新（默认每日 02:00），同一数据源加分布式锁防并发。 - 采集 diff 生成 schema_change 记录（add/drop/modify column），推送到站内消息。 - 采集失败重试 3 次，仍失败标记数据源 status=failed 并告警。 产出：internal/meta/service/collect_job.go、变更记录表与 API。 验收：删除源表一列后，站内消息出现 drop_column 且含表名与列名。

T0209 · 敏感字段识别 P1 1.5d

目标：为脱敏与合规提供依据。 要点 - 规则两层：列名正则（phone|mobile|id_card|email|bank_card|address）+ 值采样（每列最多 200 行，正则命中率 > 80% 判定）。 - 采样必须 LIMIT，禁止全表扫描；对超大表随机采样。 - 结果写 column.pii（none/low/medium/high）与 pii_reason，允许人工覆盖并记录操作人。 产出：internal/meta/service/pii.go、识别规则配置。 验收：样例库中手机号/邮箱列识别准确率 ≥ 90%；人工修改后不被下次采集覆盖。

T0210 · 元数据搜索与标签 P1 1.5d

目标：几万张表里能快速找到目标表。 要点 - PG 全文检索（to_tsvector('simple', name||comment)）+ pg_trgm 模糊匹配双通道，中文按字切分。 - 支持按 layer/datasource/tag/owner 过滤，结果高亮命中词。 - 标签 CRUD + 批量打标；标签可作为模型编译的软约束（如 pii=high 必须有脱敏）。 产出：搜索 API、标签表与 service。 验收：10 万行元数据下关键词搜索 p95 ≤ 100ms；中文表名可命中。
