# E09 · 前端与可视化 ｜ E10 · 交付与工程化

> 前端不是「把接口包一层」。管道编排画布、实时日志、血缘图这三块决定了产品的专业度，必须有明确的交互规格，否则 AI 会写出「能点但不好用」的页面。

> **实施说明（技术选型调整）**
>
> 卡片里写的是 Vite + React 18 + Ant Design + Monaco + ECharts。实际实现改为
> **原生 JS + `go:embed`**，没有前端构建链。
>
> 理由只有一条：交付目标是单个二进制。引入 Vite 后，`go build` 之前必须
> `pnpm build`，Dockerfile 要加 Node 阶段，CI 多一条工具链，升级时还要处理
> node_modules 与 lock 漂移。而这个系统的界面复杂度（表格、表单、SVG 图表、
> 拖拽）用原生 DOM 完全够，体积还小一个数量级。
>
> 代价与替代：
> - 组件库 → `components.js` 自己实现 ProTable / SchemaForm / SqlEditor / ConfirmDanger；
> - Monaco → textarea 叠层 + 轻量补全（`sqled` 系列样式），够用但不如 Monaco；
> - ECharts → 手写 SVG（折线/面积/饼/柱），图表类型少但可控；
> - TanStack Query → `api()` 封装 + 页面级 loading/error 状态；
> - TS strict → 没了类型检查，靠接口契约测试与后端 schema 兜底。
>
> 验收项按「功能」判定，不按「指定库」判定：1 万行窗口渲染、拖 4 个图表保存、
> 类型切换保留字段映射、空数据提示，都已实测通过。

## E09 前端与可视化（24 人日）

#### T0901 · 前端工程与设计系统  `P0` `2d`
**目标**：统一骨架，后续页面不用重复造壳。
**要点**
- Vite + React 18 + TS strict + Ant Design 5 + Tailwind（仅布局）；路由 `react-router` v6，按模块懒加载。
- 目录：`pages/`（按域）、`components/`（通用）、`features/`（业务组件）、`api/`（生成代码 + fetch 封装）、`stores/`、`hooks/`。
- 布局：左侧一级导航（数据源/模型/管道/运维/质量/血缘/BI/设置），顶部工作空间切换 + 环境标识（dev 用黄色条，prod 用红色条，防误操作）。
- 主题：亮/暗双主题，主色可配；中英文 i18n（先做 zh-CN，en 预留 key）。
- 统一 Loading / Empty / Error 三态组件；所有请求走 TanStack Query，含重试与失效策略。
**产出**：工程骨架、布局、主题、请求层。
**验收**：`pnpm build` 无 TS 错误；切换工作空间全站数据刷新；prod 环境视觉警示可见。

#### T0902 · 通用业务组件  `P0` `3d`
**目标**：表格、表单、SQL 编辑器是高频复用件。
**要点**
- `ProTable` 封装：列配置、分页、排序、筛选、列显隐、导出、批量选择；空态与骨架屏。
- `SchemaForm`：由 JSON Schema 生成表单（模型/管道/质量规则共用），支持字段联动与校验信息定位。
- `SqlEditor`：Monaco + 自定义补全（表名、列名、模板函数 `ref`/`src`/`macro`），格式化，只读模式，diff 模式。
- `ConfirmDanger`：危险操作二次确认（输入资源名），记录操作原因。
**产出**：`components/{ProTable,SchemaForm,SqlEditor,ConfirmDanger}`。
**验收**：SchemaForm 能渲染模型 DSL 全部字段；SQL 编辑器补全含当前工作空间的表；表格 1 万行虚拟滚动流畅。

#### T0904 · 模型设计器  `P0` `3d`
**目标**：不写 YAML 也能建表。
**要点**
- 三栏：左-模型列表（按层分组），中-字段表格（增删改、拖拽排序、类型下拉带引擎提示），右-属性面板（分区/TTL/物化/标签）。
- 顶部 Tab：字段 / DDL 预览 / 版本历史 / 血缘 / 质量规则。

**产出**：`pages/model/*`。
**验收**：新增字段后 DDL 预览即时更新；发布 breaking 变更被前端拦截；版本 diff 与后端一致。

#### T0905 · 管道可视化编排  `P0` `5d`
**目标**：这是产品的门面，必须好用。
**要点**
- 基于 AntV X6：自定义节点（图标+名称+状态徽标+资源组色条）、正交连线、锚点吸附、连线校验（禁止成环、禁止 source 有入边）。
- 左侧节点面板（拖拽入画布），右侧属性面板（随选中节点切换表单，复用 `SchemaForm`）。
- 画布能力：缩放（滚轮 + 快捷键）、框选、多选移动、对齐辅助线、自动布局（Dagre，左→右）、小地图、全屏。
- 顶部工具栏：保存草稿、校验、Dry-run、发布、版本切换、撤销/重做（Ctrl+Z/Y）。
- 节点状态：运行中呼吸灯、成功绿、失败红并显示错误角标；点击节点右侧抽屉展示日志（SSE）。
- 快捷键：Delete 删除、Ctrl+C/V 复制粘贴、Ctrl+S 保存、空格拖拽画布。
- 性能：500 节点时拖拽 ≥ 40fps，采用分层渲染与连线批量更新。
**产出**：`pages/pipeline/editor/*`、`components/graph/*`。
**验收**：拖出 10 节点连成 DAG 并发布成功；成环连线被拒绝并提示；500 节点画布拖拽流畅；刷新后布局还原。

#### T0906 · 运维中心  `P0` `3d`
**目标**：出了问题 30 秒内定位。
**要点**

**验收**：失败实例 3 次点击内能看到错误 SQL 片段；日志实时刷新延迟 ≤ 1s；补数进度与实际一致。

#### T0907 · 血缘图  `P1` `2d`

#### T1006 · CLI 完善  `P2` `2d`
**目标**：一切可脚本化、可进 GitOps。
**要点**
- `apply/plan/export` 实现 Terraform 式 diff（`+ ~ -`），破坏性变更需 `--force`。
- `godw run --watch` 流式输出日志直到结束，退出码反映结果（0 成功 / 1 失败）。
- `godw export` 导出的 YAML 能原样 `apply` 回去（往返一致性）。
**产出**：`internal/cli/*`。
**验收**：`export | apply` 往返无 diff；`run --watch` 失败时退出码为 1。
