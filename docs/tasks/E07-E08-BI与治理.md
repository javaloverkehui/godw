# E07 · 语义层与 BI ｜ E08 · 治理与安全

> 这一层决定「业务能不能自己用」。核心不是图表多好看，而是**指标口径唯一、权限可下推、查询不出事故**。

---

## E07 语义层与 BI（16 人日）

#### T0701 · 数据集定义  `P0` `2d`
**目标**：把物理表封装成业务能理解的「主题」。
**要点**
- `dataset = base_model + joins + dimensions + measures + filters`；`joins` 支持 `left/inner`，必须有显式 `on` 条件，禁止笛卡尔积。
- 维度：字段 + 显示名 + 类型（`categorical/time/number`）+ 是否可作为筛选；时间维度自动派生 `day/week/month/quarter/year` 粒度。
- 度量：`agg(sum/count/count_distinct/avg/max/min)` + 表达式 + 格式（金额/百分比/整数）+ 单位。
- 数据集只能引用 `dwd/dws/ads`，引用 `ods` 直接拒绝（保护原始层）。
**产出**：`internal/semantic/dataset.go`、校验器。
**验收**：引用 ods 被拒；join 无 on 条件被拒；维度派生粒度齐全。

#### T0702 · 指标口径管理  `P0` `2d`
**目标**：同一个「GMV」全公司只有一个算法。
**要点**
- 指标 = 名称（唯一）+ 所属 dataset + 表达式 + 聚合 + 格式化 + 业务口径说明 + 负责人。
- 同名指标不允许重复定义；改名保留别名映射，避免看板失效。
- 指标变更走版本：`metric_version` 记录表达式历史，看板绑定版本，避免口径漂移导致历史看板变化。
- 支持指标血缘：指标 → dataset → 模型 → 源表，可在血缘图中展示。
**产出**：`internal/semantic/metric.go`、版本表。
**验收**：重复指标名返回 409；改口径后旧看板仍按旧版本渲染；血缘可查。

#### T0703 · 查询构建器  `P0` `3d`
**目标**：把「维度+度量+筛选」翻译成正确 SQL。
**要点**
- 生成结构：`SELECT dims, aggs FROM base [joins] WHERE filters AND rls GROUP BY dims [HAVING] ORDER BY ... LIMIT ...`。
- 时间粒度用 `Dialect.DateTrunc`；同环比用窗口函数（`LAG`）或自连接，优先窗口（引擎支持时）。
- 空结果处理：无 GROUP BY 的聚合查询必须返回一行（`SUM` 为 NULL 时转 0，按指标配置）。
- 所有标识符走 `QuoteIdent`；筛选值参数化，禁止拼接。
- 生成 SQL 带注释标明来源 dataset/metric，便于排查。
**产出**：`internal/semantic/querybuilder.go`、golden 测试。
**验收**：20 组查询快照正确；同环比在四引擎结果一致；SQL 注入用例（值含 `' OR 1=1`）不生效。

#### T0704 · 查询 API 与结果协议  `P0` `2d`
**目标**：前端拿到就能直接画图。
**要点**
- 请求：`{dimensions, measures, filters, timeRange, granularity, orderBy, limit, offset}`；响应：`{columns:[{name,label,type,format}], rows:[...], total, sql, took}`。
- 行数上限默认 10000，超出返回截断标记；导出走独立接口（流式）。
- 支持 `debug=true` 返回生成的 SQL（仅 admin）。
- 查询超时默认 30s，可配；超时返回 `50003 query timeout` 而非 500。
- 慢查询（> 5s）记录到 `slow_query` 表并在运维页可见。
**产出**：`internal/api/http/dataset_query.go`。
**验收**：返回列元数据完整；超过上限有截断标记；超时错误码正确。

#### T0705 · 行级权限与列级脱敏  `P0` `2d`
**目标**：不同人看到不同数据。
**要点**
- RLS 规则：`{dataset, column, operator, valueFrom: user.attr|static}`，编译为 SQL 条件注入 `WHERE`，必须在聚合前生效。
- 用户属性来自 JWT claims（`region`、`dept`、`level`）；无匹配规则时默认拒绝（fail-closed）而非放行。
- 列级脱敏：按 `column.pii` 与角色决定 `mask/replace/hide`；在 SELECT 列表就替换，不能让前端拿到明文。
- 所有规则变更审计；提供「预览某用户将看到的 SQL」调试接口。
**产出**：`internal/auth/rls.go`、mask 函数。
**验收**：region=华东 的用户只能查到本区域数据；high PII 列对 viewer 角色返回 `***`；规则缺失时拒绝查询。

#### T0706 · 缓存与预聚合  `P1` `2d`
**目标**：看板打开要快，别每次都扫全表。
**要点**
- 结果缓存 key = `hash(dataset + 规范化后的查询 + 用户权限指纹)`；TTL 按 dataset 配置（默认 5 分钟）。
- 缓存失效：模型发布/补数完成时按 `dataset` 维度失效；也支持手动清空。
- 预聚合：对高频看板配置「定时物化到 ADS」；查询命中预聚合表时自动改写 SQL。
- 缓存后端抽象（内存/Redis），单机默认内存 LRU（上限 512MB）。
**产出**：`internal/semantic/cache.go`、预聚合配置。
**验收**：二次查询 p95 降低 80%；权限不同的两个用户不共享缓存；发布后缓存失效。

#### T0707 · 图表配置模型  `P0` `2d`
**目标**：图表配置可存、可迁移、可复用。
**要点**
- 配置：`{type, dataset, dimensions, measures, encoding:{x,y,series,size,color}, style, filters}`。
- 支持类型：折线、柱状、堆叠柱、饼图、环形、指标卡、表格、散点、地图（按需）。
- 编码映射校验：如饼图只能 1 维度 + 1 度量，校验失败给出明确提示。
- 配置版本化，看板引用图表 ID，修改图表需确认是否影响引用它的看板。
**产出**：`internal/bi/chart.go`、schema。
**验收**：非法编码组合被拒；同一图表被 2 个看板引用时提示影响面。

#### T0708 · 看板模型  `P1` `2d`
**目标**：拖拽布局、全局筛选、联动。
**要点**
- 栅格布局（24 列），每个图表存 `{x,y,w,h}`；响应式断点 3 档。
- 全局筛选器绑定到多个图表的字段；联动：点击某图表的维度值 → 其他图表按该值过滤。
- 看板级参数（如 `bizdate`）与 URL 同步，便于分享具体状态。
- 保存草稿/发布两态；发布后生成快照，回滚可用。
**产出**：`internal/bi/dashboard.go`、布局校验。
**验收**：布局越界/重叠校验；URL 带参数打开后筛选生效；发布快照可回滚。

#### T0709 · 导出与订阅  `P1` `2d`
**目标**：数据能带走、能定时送达。
**要点**
- 导出 CSV/Excel：流式写（不load全量到内存），大结果集走对象存储 + 预签名 URL。
- 订阅：按 cron 生成快照（图片或 Excel）→ 邮件/webhook 推送；失败重试 3 次。
- 导出记录审计（谁、何时、导出了什么、多少行），high 级数据导出需审批（可配置）。
- 文件名规范：`{dashboard}_{yyyyMMddHHmm}.xlsx`。
**产出**：`internal/bi/export.go`、`subscription.go`。
**验收**：100 万行导出内存增长 < 200MB；订阅按时送达；导出记录可查。

#### T0710 · 分享与嵌入  `P2` `1.5d`
**目标**：看板能发给不用登录的人。
**要点**
- 只读分享：生成 `share_token`（随机 32 位），可设有效期与密码；只读、不可导出（可配）。
- iframe 嵌入：提供 embed 路由与 `X-Frame-Options` 白名单。
- 分享链接的查询强制走该看板绑定的数据集与 RLS 的「匿名策略」，不允许越权。
- 支持随时吊销 token。
**产出**：分享 API、embed 路由。
**验收**：吊销后链接立即失效；匿名访问不能查到未授权数据；iframe 在允许域名外被拒。

## E08 治理与安全（10 人日）

#### T0801 · 用户、角色与权限  `P0` `2d`
**目标**：谁能看什么、改什么，说清楚。
**要点**
- 内置角色：`owner`（工作空间全权）、`admin`（系统配置）、`editor`（建模/编排）、`runner`（触发/重跑）、`viewer`（只读）。
- 资源级 ACL：workspace / datasource / model / pipeline / dashboard 五类资源，支持「角色继承 + 单资源授权」。
- Casbin model：`sub, dom(workspace), obj(resource), act`；策略存库，支持热加载。
- 权限校验中间件在路由层完成，service 层再做一次资源归属校验（防越权 ID 猜测）。
**产出**：`internal/auth/rbac/*`、casbin model、策略种子。
**验收**：viewer 调用发布接口返回 403；跨 workspace 访问返回 404（不泄露存在性）。

#### T0802 · 认证与会话  `P0` `1.5d`
**目标**：能登录、能接企业账号。
**要点**
- 本地账号：bcrypt（cost 12）+ 登录失败锁定（5 次 / 15 分钟）。
- JWT：HS256，`access_token` 2h，`refresh_token` 7d；登出用黑名单（Redis 或 DB）。
- 预留 OIDC：配置 `issuer/client_id/secret`，实现授权码流程；LDAP 作为备选。
- 密码策略：长度 ≥ 10、含大小写数字；首次登录强制改密（可配）。
**产出**：`internal/auth/*`、登录/刷新/登出 API。
**验收**：错误密码 5 次后锁定；token 过期返回 401 且可刷新；OIDC 登录可跑通 mock server。

#### T0803 · 数据分级与脱敏  `P0` `1.5d`
**目标**：敏感数据有标记、有策略、有执行。
**要点**
- 分级：`public/internal/confidential/secret`，映射到列的 `pii` 等级。
- 脱敏策略：`mask`（保留首尾）、`hash`（加盐 SHA256）、`replace`（固定值）、`hide`（列不下发）。
- 策略绑定「角色 + 资源」，在查询构建与导出两处同时生效（漏一处等于没做）。
- 提供「脱敏预览」：给定角色与列，展示脱敏结果样例。
**产出**：`internal/auth/mask.go`、策略配置。
**验收**：同一列对 admin 明文、对 viewer 脱敏；导出文件同样脱敏；预览结果与实际一致。

#### T0804 · 审计日志  `P0` `1.5d`
**目标**：关键操作可追责。
**要点**
- 记录范围：登录/登出、增删改、发布/回滚、触发/重跑/终止、权限变更、导出、分享。
- 字段：`actor, action, resource_type, resource_id, before, after, ip, ua, request_id, ts`。
- append-only：只允许插入，DB 层用独立账号（无 UPDATE/DELETE 权限）；可选哈希链（`prev_hash`）防篡改。
- 查询：按人/资源/时间/动作过滤，支持导出。
**产出**：`internal/auth/audit.go`、审计查询 API。
**验收**：发布模型产生一条含 before/after 的记录；应用账号无法删除审计行；查询过滤准确。

#### T0805 · 多租户隔离  `P1` `1.5d`
**目标**：一套部署服务多个团队，数据不串。
**要点**
- 隔离模型：共享库 + `workspace_id` 行级隔离（默认）；预留「独立 schema」模式给大客户。
- 所有 repo 方法强制带 `workspace_id`（sqlc 查询模板统一注入），漏带由测试拦截（查询审计：扫描所有 SQL 是否含 workspace 条件）。
- 资源配额：每 workspace 限制数据源数、管道数、日任务数、并发数。
- 跨租户引用（A 的管道写 B 的模型）直接拒绝。
**产出**：隔离规范、配额校验、审计测试。
**验收**：构造跨租户请求返回 404；超配额创建返回 429；静态扫描无漏带 workspace 的查询。

#### T0806 · 密钥与凭据管理  `P1` `1d`
**目标**：密码不泄露、可轮换。
**要点**
- 主密钥来自环境变量或 KMS；数据源密码 AES-256-GCM 加密，`secret.key_version` 支持轮换（新写用新版本，旧数据按需重加密）。
- 日志/错误/审计中禁止出现密码与 token（正则过滤 + 单测）。
- 提供 `godw secret rotate` 命令批量重加密。
**产出**：`internal/auth/secret/*`、轮换命令。
**验收**：全库搜索无明文密码；轮换后旧数据仍可解密；日志脱敏测试通过。

#### T0807 · 合规与数据生命周期  `P2` `1d`
**目标**：满足基本的合规要求。
**要点**
- 数据保留策略：按模型配置保留期，到期由维护任务归档/删除，并记录审计。
- 导出审批：high 级数据导出需审批流（可先做「申请-批准」两态）。
- 删除权：支持按主键删除指定用户数据（生成删除任务并留痕）。
**产出**：保留策略配置、删除任务。
**验收**：到期数据被归档且审计可查；未审批导出被拒。

#### T0808 · 用量与成本核算  `P2` `1.5d`
**目标**：知道钱花在哪。
**要点**
- 采集：每任务扫描字节、CPU 时间、写入行数；存储按表大小日快照。
- 归集：按 workspace / pipeline / model 聚合，支持按天/周/月查看。
- 成本单价可配（元/GB 扫描、元/GB 存储），输出估算账单。
- 提供 Top N 消耗排行，辅助优化。
**产出**：`internal/obs/usage/*`、报表 API。
**验收**：跑一条管道后用量可见；Top N 排行正确；月度汇总与明细一致。
