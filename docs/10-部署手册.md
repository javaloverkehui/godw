# 部署手册

面向「把 GoDW 装到一台新机器上」的场景。三条路径，按需要选：

| 场景 | 方式 | 耗时 |
| --- | --- | --- |
| 本地试用 / 演示 | `make demo` | 5 分钟 |
| 单机部署 | Docker Compose | 10 分钟 |
| Kubernetes | Helm chart | 20 分钟 |

---

## 1. 本地试用

```bash
make build          # 编译 server / worker / cli 到 bin/
make up             # 起 postgres/redis/mysql/clickhouse/minio
make migrate        # 建元数据表
make demo           # 灌数 + 三条管道 + 三个看板
make run            # 启动控制面，浏览器打开 http://localhost:8080
```

`make demo` 是幂等的：重跑会重建演示数据，结果与上次一致。它同时是一次端到端自检——
如果它跑不通，说明依赖或迁移有问题，先解决再往下走。

默认管理员：`admin@godw.local` / `admin12345`（由 `auth.bootstrap_admin/pass` 决定）。

## 2. 单机部署（Docker Compose）

### 2.1 准备

```bash
cp .env.example .env
```

至少要改两个值，否则 compose 直接拒绝启动（这是故意的，默认口令上线是事故源头）：

```ini
GODW_DB_PASSWORD=<强口令>
GODW_JWT_SECRET=<32 字节以上随机串>
```

生成随机串：

```bash
openssl rand -base64 32
```

### 2.2 起服务

```bash
docker compose -f deploy/docker-compose.prod.yaml up -d
docker compose -f deploy/docker-compose.prod.yaml logs -f server | grep -i "初始管理员"
```

首次启动会自动执行迁移并打印一次初始密码。若已通过 `GODW_ADMIN_PASSWORD` 指定，
日志里不会出现明文。

### 2.3 编排里做了什么

不是把进程塞进容器就完事，每条都对应一类线上事故：

| 配置 | 解决的问题 |
| --- | --- |
| `read_only: true` + `tmpfs: /tmp` | 容器被写坏（日志暴涨、临时文件堆积）后重启即恢复 |
| server / worker 分进程 | 跑批把控制面拖死时，界面仍然可用 |
| `no-new-privileges` | 容器内提权 |
| 健康检查走 `/readyz` | 端口通不代表 schema 迁移完成，`readyz` 才看得到真实状态 |
| 元数据库独立卷 + 每日备份 | 应用容器重建不带走元数据 |
| `logging.options.max-size` | 日志写满磁盘导致整机不可用 |

### 2.4 备份

```bash
docker compose -f deploy/docker-compose.prod.yaml exec -T postgres \
  pg_dump -U godw -Fc godw > backup/godw-$(date +%F).dump
```

恢复：

```bash
docker compose -f deploy/docker-compose.prod.yaml exec -T postgres \
  pg_restore -U godw -d godw --clean --if-exists < backup/godw-2026-11-09.dump
```

`deploy/backup/` 已挂进 postgres 容器，也可以交给宿主机的 cron。

### 2.5 升级

```bash
docker compose -f deploy/docker-compose.prod.yaml pull
docker compose -f deploy/docker-compose.prod.yaml up -d migrate   # 先迁移
docker compose -f deploy/docker-compose.prod.yaml up -d server worker
```

迁移是幂等的（`schema_migration` 记录版本），重复执行不会重放。
回滚只能靠备份——**破坏性 DDL 不回滚**，这是有意的：自动回滚比不滚更危险。

### 2.6 优雅退出

容器收到 `SIGTERM` 后：

1. server 停止接收新请求，`/healthz` 立即返回失败（让负载均衡摘掉）；
2. worker 停止领取新实例，把正在跑的节点执行完；
3. 超过 `scheduler.lease_sec` 未完成的任务由租约超时接管，下次启动续跑。

强制 `SIGKILL` 时，运行中的实例会在租约到期后被重新领取，不会永久卡住。

## 3. Kubernetes（Helm）

```bash
helm install godw ./deploy/helm/godw \
  --namespace godw --create-namespace \
  --set image.repository=ghcr.io/godw/godw \
  --set image.tag=0.1.0 \
  --set env.GODW_DB_HOST=pg.example.internal \
  --set env.GODW_DB_PASSWORD=<口令> \
  --set env.GODW_AUTH_JWT_SECRET=<随机串>
```

先用 `helm template` 检查渲染结果，不碰集群：

```bash
helm template godw ./deploy/helm/godw -f my-values.yaml > /tmp/godw.yaml
helm lint ./deploy/helm/godw
```

### 3.1 values 覆盖项

| 键 | 说明 | 默认 |
| --- | --- | --- |
| `image.repository` / `image.tag` | 镜像 | `ghcr.io/godw/godw:latest` |
| `replicaCount` | server 副本数 | `2` |
| `worker.replicaCount` | worker 副本数 | `2` |
| `resources` | 资源限额 | 见 `values.yaml` |
| `env.GODW_DB_*` | 外部元数据库 | 内置 postgres |
| `ingress.enabled` / `host` | 对外入口 | `false` |
| `persistence.size` | 内置 PG 容量 | `20Gi` |

### 3.2 就绪与存活

- **readiness** 走 `/readyz`：schema 版本未对齐时返回 503，滚动更新不会把流量打到半迁移的实例；
- **liveness** 走 `/healthz`：只判断进程是否卡死，不查数据库，避免数据库抖动导致整批 Pod 重启。

### 3.3 迁移 Job

chart 里 `migrate-job.yaml` 是 `pre-install,pre-upgrade` hook。多副本同时启动时只有它先跑，
server 启动时发现 schema 版本落后会直接失败——宁可起不来，也不要半套 schema 接流量。

## 4. 配置项

完整清单见 `config.dev.yaml` 注释。常改的几项：

| 配置 | 说明 |
| --- | --- |
| `server.addr` | 监听地址，默认 `:8080` |
| `db.max_conns` | 元数据库连接池上限，建议 ≤ PG `max_connections` 的 1/4 |
| `scheduler.max_concurrent` | 单实例并发执行数 |
| `scheduler.tick_sec` | 调度扫描间隔，默认 10s |
| `scheduler.lease_sec` | 实例租约，worker 崩溃后多久被接管 |
| `log.level` / `log.format` | `json` 便于采集，`text` 便于人看 |

密码、JWT 密钥**只走环境变量**。配置文件里写了也会被环境变量覆盖，
且 `config.dev.yaml` 提交到仓库前已被 `.gitignore` 排除敏感值。

## 5. 上线检查清单

- [ ] `GODW_DB_PASSWORD`、`GODW_AUTH_JWT_SECRET` 已改，不是默认值
- [ ] 元数据库有每日备份，且**演练过一次恢复**
- [ ] `/readyz` 接入了负载均衡健康检查
- [ ] 日志已接入采集（容器 `json-file` 只保留 5×50MB，不采集会丢）
- [ ] 告警通道已配置（`alert.webhook_url` 或页面里的通知设置）
- [ ] 初始管理员密码已改
- [ ] `make smoke` 或 `scripts/smoke.sh` 在新环境跑通一次

## 6. 常见问题

**`readyz` 返回 503，日志说 schema 版本落后**
迁移没跑。`docker compose up migrate` 或 `./bin/godw-cli migrate`。

**server 起来了但页面 401**
前端用 JWT，浏览器里残留了旧环境的 token。清 `localStorage` 后重新登录。

**worker 一直领不到任务**
检查 `instance` 表里是否有 `status='queued'` 且 `resource_group` 与 worker 匹配。
worker 只领取自己资源组内的任务。

**ClickHouse 连接失败但其他库正常**
默认构建不含 ClickHouse 驱动以外的特殊依赖；若使用 DuckDB，镜像需带 `-tags duckdb` 构建
（`docker build --build-arg BUILD_TAGS=duckdb`）。

**升级后页面是旧版**
UI 走 `go:embed`，镜像更新才会变。确认 `image.tag` 真的变了（`latest` 不会自动拉）。
