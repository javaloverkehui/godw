# 安装与运行（离线包）

这份文档面向**拿到压缩包、想在自己机器上跑起来**的人。不需要 Go 环境，不需要读源码。

---

## 1. 包里有什么

解压后是一个 `godw-<版本>-<平台>/` 目录：

| 路径 | 用途 |
| --- | --- |
| `bin/godw-server` | 控制面进程：HTTP API、内嵌界面、内嵌调度器 |
| `bin/godw-worker` | 数据面进程：只领任务执行，不起 HTTP；不启动也能跑（server 自带执行器） |
| `bin/godw-cli` | 运维命令行：迁移、自检、提交定义、跑管道、导血缘 |
| `config.dev.yaml` | 开发配置（连本机 PostgreSQL，演示用） |
| `config.example.yaml` | 全量配置样例，带注释 |
| `migrations/` | 元数据库表结构（已编进二进制，目录留着方便排错） |
| `deploy/` | docker compose、Dockerfile、Helm chart、PG 初始化 SQL |
| `examples/` | 示例模型/管道/指标/看板定义，`demo/` 是演示数据 |
| `scripts/` | `demo.sh` 一键演示、`smoke.sh` 冒烟、`seed.sh` 灌样例 |
| `docs/` | 架构、元数据模型、运维手册等 12 份文档 |

配置里的敏感项（数据库口令、JWT 密钥）不落盘，启动时用环境变量注入。

---

## 2. 先决条件

**必需：一个 PostgreSQL 14+**。它只存元数据（模型、管道、实例、血缘、审计），不存业务数据。

**可选：Docker**。有 Docker 的话，`deploy/docker-compose.dev.yaml` 会一并起 MySQL / ClickHouse / Redis / MinIO，演示链路更完整。

### 2.1 有 Docker

```bash
docker compose -f deploy/docker-compose.dev.yaml up -d
```

等 postgres 变成 healthy（约 5 秒）。容器里的库名/账号/口令都是 `godw`。

### 2.2 没有 Docker（macOS 本机装 PG）

```bash
brew install postgresql@16
brew services start postgresql@16

# 建一个和配置对齐的账号与库
createuser -s godw
psql -d postgres -c "ALTER USER godw PASSWORD 'godw';"
createdb -O godw godw
```

Linux 上等价操作是 `apt install postgresql` + `sudo -u postgres createuser -s godw`。

## 3. 跑起来（三条命令）

```bash
cd godw-1.0.0-darwin-amd64

# 口令必须和上面 PG 的实际口令一致；JWT 密钥随便给个长串
export GODW_DB_PASSWORD=godw
export GODW_AUTH_JWT_SECRET=dev-secret-change-me

# 1) 建元数据表（幂等，可重复执行）
./bin/godw-cli migrate --config config.dev.yaml

# 2) 自检：配置 / 数据库 / 连接器 / 数据源
./bin/godw-cli doctor --config config.dev.yaml

# 3) 一键演示：灌 12 万行样例数据 → 建模型 → 发布管道 → 回填 → 质量门禁
bash scripts/demo.sh config.dev.yaml
```

`demo.sh` 结束会打印每层行数与看板列表。它是端到端的：跑不通说明依赖或迁移有问题，
先按提示解决，别急着往下走。

启动控制面：

```bash
./bin/godw-server --config config.dev.yaml
```

浏览器打开 <http://localhost:8080>，账号 `admin@godw.local`，口令 `admin12345`。

## 4. 界面上看什么

| 页面 | 能看到 |
| --- | --- |
| 总览 | 今日实例数、成功率、各层行数、最近失败 |
| 模型 | 四层模型与字段定义、版本历史、发布/回滚、DDL 预览 |
| 管道 | 节点编排、依赖关系、手动触发与补数 |
| 实例 | 每次运行的节点级日志与耗时，失败可重跑 |
| 质量 | 规则、校验结果、门禁拦截记录 |
| 血缘 | 表级 DAG，点节点下钻到字段级；可切上/下游看影响面 |
| 指标 / 看板 | 指标定义与图表，支持导出 CSV |
| 数据源 | 增删数据源、测试连通性、采集元数据 |

## 5. 接自己的数据库

界面「数据源 → 新建」，类型选 `postgres` / `mysql` / `clickhouse`，填连接信息即可。
保存时就会试连，失败会直接告诉你错在哪（而不是等到跑管道才报）。

接上之后：数据源页「采集」→ 模型页从源表生成脚手架 → 改字段 → 发布 → 建管道。

> DuckDB 是嵌入式引擎，驱动要 CGO，**默认包里没有编进去**。需要它请用源码包
> `go build -tags duckdb`，详见第 8 节。默认二进制遇到 `type: duckdb` 会明确提示这一点。

## 6. 常见问题

**双击/运行二进制时 macOS 提示「无法验证开发者」**

下载来的文件带隔离属性，执行一次即可：

```bash
xattr -dr com.apple.quarantine godw-1.0.0-darwin-amd64
```

**`password authentication failed for user "godw"`**

`GODW_DB_PASSWORD` 和你 PG 里实际口令不一致。用 `psql -U godw -d godw -h 127.0.0.1` 验证一下。

**`connection refused` / `dial tcp 127.0.0.1:5432`**

PG 没起。macOS：`brew services list` 看状态；Docker：`docker compose ps`。

**8080 端口被占**

改 `config.dev.yaml` 的 `server.addr: ":8081"`，或用 `--config` 指向另一份配置。

**迁移能重复跑吗**

能。`migrations/` 里的脚本按版本号记录在 `schema_migrations` 表，已执行的会跳过。

**数据存在哪**

元数据在 PG 的 `public` schema（`godw_*` 表）；业务数据在同一个 PG 实例的 `dw` 库
（演示默认用 PG 当数仓）。生产上把数据源指向独立的 MySQL/ClickHouse 即可。

**要重置**

```bash
# Docker
docker compose -f deploy/docker-compose.dev.yaml down -v
# 本机 PG
dropdb godw && createdb -O godw godw   # 再跑一次 migrate
```

## 7. 目录外的东西

- 运行期工作目录：`./data`（`executor.work_dir`），存执行临时文件，可随时删。
- 日志：默认输出到 stdout，`log.format: json` 可切成结构化日志接采集。
- 单机多副本：直接多起几个 `godw-worker`，靠 `SKIP LOCKED` + 租约保证不重复执行。

## 8. 从源码构建

```bash
# 需要 Go 1.25+
make build                 # 产出 bin/ 三个二进制
make test                  # 单元测试
make test-integration      # 真实引擎集成测试（需 Docker 起 pg/mysql/ch）

# 带 DuckDB（需要 CGO 与本地 C 工具链）
go build -tags duckdb -o bin/godw-server ./cmd/godw-server
```

Docker 镜像：

```bash
make image                 # docker build -f deploy/Dockerfile -t godw:dev .
```

Kubernetes：`deploy/helm/` 下有 chart，`values.yaml` 改镜像与副本数即可。
