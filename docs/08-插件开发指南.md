# 插件开发指南

> 目标：新增一个数据源引擎（比如 Doris、Trino、SQLite）或一种节点类型，**不改核心代码**。
> 全部扩展点都是 Go 接口 + 注册表，没有反射、没有动态加载。

## 1. 扩展点总览

| 扩展点 | 接口 | 注册位置 | 影响面 |
|---|---|---|---|
| 数据源引擎 | `connector.Connector` | `internal/connector/registry.go` | 连接、查询、执行、元数据采集 |
| SQL 方言 | `dialect.Dialect` | `internal/dialect/engines.go` | 引号、占位符、分页、日期函数、DDL 类型 |
| 节点类型 | `node.Runner` | `internal/pipeline/node/executor.go` | 管道里多一种算子 |
| 质量规则 | `quality.Build` 的分支 | `internal/quality/quality.go` | 多一种校验方式 |
| 脱敏方式 | `service.Mask` 的分支 | `internal/meta/service/governance.go` | 多一种掩码算法 |

## 2. 新增数据源引擎

以 SQLite 为例，四步：

### 2.1 实现 Connector

```go
// internal/connector/sqlite/sqlite.go
package sqlite

import (
    "context"
    "database/sql"
    _ "modernc.org/sqlite"

    "github.com/godw/godw/internal/connector"
    "github.com/godw/godw/internal/dialect"
)

type Conn struct{ db *sql.DB }

func Open(ctx context.Context, spec connector.Spec) (connector.Connector, error) {
    path, _ := spec.Config["path"].(string)
    db, err := sql.Open("sqlite", path)
    if err != nil {
        return nil, err
    }
    if err := db.PingContext(ctx); err != nil {
        return nil, err
    }
    return &Conn{db: db}, nil
}

func (c *Conn) Type() string { return "sqlite" }

func (c *Conn) Dialect() dialect.Dialect { return dialect.Must("sqlite") }

// Capabilities 决定上层能用哪些写入策略。如实声明，不要为了「看起来强」全填 true。
func (c *Conn) Capabilities() connector.Capability {
    return connector.Capability{
        MergeUpsert:      true,  // SQLite 支持 ON CONFLICT
        InsertOverwrite:  false,
        TransactionalDDL: true,
        Returning:        true,
    }
}

func (c *Conn) Query(ctx context.Context, sqlText string, args ...any) (connector.Rows, error) {
    // 返回实现 connector.Rows 的包装；参考 internal/connector/memrows.go
}

func (c *Conn) Exec(ctx context.Context, sqlText string, args ...any) (connector.Result, error) {
    res, err := c.db.ExecContext(ctx, sqlText, args...)
    // ...
}

func (c *Conn) Ping(ctx context.Context) error { return c.db.PingContext(ctx) }
func (c *Conn) Close() error                   { return c.db.Close() }

// 可选：实现 Tables/Columns 让元数据采集可用
```

### 2.2 实现 Dialect

```go
// internal/dialect/engines.go 里追加
type sqliteDialect struct{ base }

func (sqliteDialect) Name() string { return "sqlite" }
func (d sqliteDialect) QuoteIdent(s string) string { return `"` + strings.ReplaceAll(s, `"`, `""`) + `"` }
func (d sqliteDialect) Placeholder(i int) string   { return "?" }
func (d sqliteDialect) LimitOffset(limit, offset int64) string {
    if offset > 0 {
        return fmt.Sprintf("LIMIT %d OFFSET %d", limit, offset)
    }
    return fmt.Sprintf("LIMIT %d", limit)
}
func (d sqliteDialect) DateTrunc(gran, col string) string {
    switch gran {
    case "month": return fmt.Sprintf("date(%s,'start of month')", col)
    case "week":  return fmt.Sprintf("date(%s,'weekday 0','-6 days')", col)
    default:      return fmt.Sprintf("date(%s)", col)
    }
}
```

再在 `init()` 里注册：

```go
func init() { Register("sqlite", func() Dialect { return sqliteDialect{} }) }
```

### 2.3 注册 Connector

```go
// internal/connector/sqlite/sqlite.go
func init() { connector.Register("sqlite", Open) }
```

并在 `cmd/godw-server/main.go` 的匿名导入里加一行：

```go
_ "github.com/godw/godw/internal/connector/sqlite"
```

### 2.4 验证清单

```bash
go build ./... && go test ./internal/connector/...
godw-cli doctor --config config.yaml        # 应列出 sqlite
```

然后用 API 建数据源 → 采集 → 建模型 → 跑管道，走一遍全链路。**特别注意**：

- 类型映射（`dialect.MapType`）要覆盖你在 `ModelSpec.Columns[].Type` 里可能用到的逻辑类型。
- 如果不支持 `INSERT OVERWRITE`，`Capabilities()` 里必须返回 `false`，上层会自动退化为 `DELETE + INSERT`。
- 如果支持事务，实现 `connector.Transactor`，写入失败才能整体回滚。

## 3. 新增节点类型

以「发送企业微信通知」为例：

```go
// internal/pipeline/node/notify.go
package node

type NotifyRunner struct{}

func (NotifyRunner) Run(ctx context.Context, in RunInput) (Stats, error) {
    webhook, _ := in.Node.Config["webhook"].(string)
    // 渲染模板、发请求、检查返回码
    return Stats{RowsAffected: 0}, nil
}
```

在 `executor.go` 的分派处加一个 case，并在 `pipeline/compile` 的节点类型白名单里登记：

```go
case "notify":
    return NotifyRunner{}.Run(ctx, in)
```

前端画布的 `NODE_TYPES` 也补一项，否则编排页看不到。

## 4. 新增质量规则

```go
// internal/quality/quality.go
case "row_count_between":
    min := number(rule.Config["min"])
    max := number(rule.Config["max"])
    out.SQL = fmt.Sprintf("SELECT COUNT(*) AS observed, 1 AS expected FROM %s", t)
    out.Expect = fmt.Sprintf("行数在 [%v, %v]", min, max)
```

约定：**SQL 必须返回 `(observed, expected)` 两列**，判定逻辑集中在调用方，新增规则不用改执行器。

## 5. 新增脱敏方式

```go
// internal/meta/service/governance.go
case "idcard":
    if len(str) < 8 { return "***" }
    return str[:4] + "**********" + str[len(str)-4:]
```

同时更新 `saveColumnPolicy` 的白名单与前端下拉项。

## 6. 测试要求

新增扩展点必须带测试，至少覆盖：

| 场景 | 断言 |
|---|---|
| 正常查询 | 返回列名、类型、行数正确 |
| 空结果 | 不 panic，返回空切片 |
| 语法错误 | 返回 `CodeExecutionFailed` 且带原 SQL |
| 事务回滚 | 中途失败后表内无残留 |
| 方言转义 | 标识符含 `"`、值含 `'` 时不注入 |

参考 `internal/dialect/dialect_test.go`、`internal/quality/quality_test.go`。

## 7. 不要做的事

- **不要在 Connector 里做业务判断**（比如「dwd 层必须 upsert」）。那是建模层的策略。
- **不要在 SQL 里拼接用户输入**。所有值走 `${var}` 渲染，渲染器会做字面量转义。
- **不要为某个引擎在核心代码里加 `if type == "xxx"`**。加分支就说明抽象漏了，应该补接口。
